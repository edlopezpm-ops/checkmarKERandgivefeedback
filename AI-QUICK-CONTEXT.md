marKER is one person's private editorial/media console. React/TypeScript/Vite serves a bilingual SPA. Hosted `/api/*` goes through a native Cloudflare Worker sole-owner email-code access layer, then to an editorial CAS repository or the Studio API. D1 holds auth, one editorial JSON workspace and separate Studio metadata. Private R2 holds originals/results. A private-owner Durable Object runs bounded native FFprobe/FFmpeg in a managed Debian/Node container. Local development substitutes loopback Vite APIs, JSON/SQLite/files and local tools; it does not emulate hosted email authentication. Supabase remains inactive adapter preparation.

There are two content workflows. Earlier editorial records link products, destination account metadata, text sources, campaigns and per-account posts; Drafting reviews/edits/exports text and explicitly records outcomes. Account metadata is not an OAuth connection. Current Space/Campaigns primarily use separate Studio material/campaign/variant entities, with retained earlier-record sections. Media campaigns do not need a destination account. Existing backend commands/forms are not all exposed as primary creation controls.

Studio capture accepts files, browser recording and literal text/ideas. Originals are retained and hash deduplicated; library cards carry optional products/classification, readiness, human speech status and rights. The deterministic planner selects compatible ready sources with confirmed rights, including explicitly reviewed licensed material, respects explicit restrictions/reuse, uses literal developed copy, and offers one proposal plus up to two alternatives. It creates editable ranges with provenance, not generated creative content. Current recipe limits are three visual segments, total 5–60 seconds, vertical 1080×1920 H.264 MP4, optional audio and PNG cover. Save, explicitly render, review actual output, approve the exact revision and export; editing invalidates approval. Export does not publish.

Server validation owns rights/references/CAS/admission. Editorial, Studio and Settings revisions differ. Two-tab stale writes return conflicts. Cross-domain product references must be safe in both commit orders. Jobs persist before enqueue; lease/watchdog/finalization/reservation states require reconciliation. An uncertain operation cannot be safely retried by assuming timeout means nothing happened. Local browser draft recovery is not a durable cross-device job queue.

Settings initially saves US$20 planning, US$10 processing, US$0 future AI, 2 GiB storage and 20-second default duration. Installed ceilings are US$20/2 GiB; processing+AI must fit total. Probe/render reserve 5/10 internal cents; enabled optional analysis would reserve 5. The ledger is not the provider invoice or a hard billing cap. Failed compute is not refunded. Admission includes pending storage. No automatic purge, capacity purchase or provider activation follows. Environment controls language/animation per browser; it does not translate stored content.

Local optional analysis exposes thumbnails/scene/low-volume/dark/static intervals under exact profile/coverage; these are navigation aids, not semantic labels/transcription. Hosted analysis is deliberately disabled by a null toolchain pin. The managed container bootstraps media packages during an overall 240-second operation deadline; native version/cold-start reliability is a real operational question.

Live AI inference, connected social posting/metrics, ads, transcription/subtitles, PWA/background upload, full retention/purge and native Android automation are not delivered. A development-only simulator can select existing sources, show mock text and save explicitly through CAS; its in-memory registry is not a production inference ledger.
