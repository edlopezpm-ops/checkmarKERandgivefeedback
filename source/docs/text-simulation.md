Run `npm run dev` and use **Editorial queue > Local text simulation** in a local session. Select a product, one of its campaigns, an existing draft destination and the campaign sources to use. Generate a simulated response, edit it, then choose **Save as editable draft**. This replaces that destination's text after explicit review. The usual queue editor can edit the saved draft again. The simulated paid example remains paused.

This development-only workflow uses a deterministic text assembly from the selected existing facts and sources. It makes no OpenAI request and selects no live model. The hosted/production build has no simulation controls. The existing sole-owner login is unchanged. Normal local storage remains `.local/workspace.json`; a separate development process can use an explicitly chosen `MARKER_LOCAL_DATA` file for disposable examples without changing the regular workspace. Do not use two development processes for the same file.

Simulation ceilings: 16 request IDs retained simultaneously, five-minute in-memory request/result lifetime, 1 MiB input snapshot and 20,000 output characters. Concurrent identical requests share one response. Reusing an ID with changed input is rejected. Source, product, campaign and destination references are validated. Error, timeout, cancellation or malformed output never saves text. Saving requires the original unchanged workspace snapshot and revision; a newer local or server edit causes a conflict and stays intact. No automatic retry occurs after a write error. Reload and review current data before generating another response.

Unsaved responses disappear on leaving the queue or reloading. Saved drafts persist through the existing local file repository and follow its manual deletion behavior. The mock registry is not a durable provider job/idempotency store. These engineering ceilings do not set OpenAI usage/time limits, provider retention, billing caps or a production retention/purge policy. Model availability, actual plan limits, request/result retention and the approved hosted request contract remain decisions after OpenAI admission.

Automated verification uses the three existing fictional scenarios: Taller Nube/LinkedIn, Biblioteca Brisa/Facebook and Estudio Faro/X. Fixtures stay synthetic and do not read or update the hosted workspace. Tests cover source compatibility, duplicates, changed requests, timeout/error/cancellation, malformed output, stale edits, expiry and replay. Browser checks exercise local selection, review, saving and subsequent editing. These checks do not establish live OpenAI eligibility, model quality or acceptance of this new increment.
